# `packages/design` — общий слой дизайна

Единственный источник дизайн-токенов и общих UI-компонентов для `web/` и `admin/`.

## Быстрый старт

```bash
# после любой правки в packages/design/
node packages/design/sync.mjs

# проверить, что приложения синхронны с источником (для CI)
node packages/design/sync.mjs --check
```

Зависимостей нет — чистый Node (>=18), запускается из любого каталога.

## Правила

1. **Токены правятся только в `tokens.mjs`.** Блок между маркерами
   `>>> НАЧАЛО СГЕНЕРИРОВАННОГО БЛОКА` / `>>> КОНЕЦ` в `<app>/src/app/globals.css`
   перезаписывается скриптом. Всё, что вне маркеров, — стили конкретного
   приложения, правятся на месте.
2. **Общие компоненты правятся только в `shared/`.** Каталоги
   `web/src/shared/` и `admin/src/shared/` — сгенерированные копии; у каждого
   файла в шапке стоит `СГЕНЕРИРОВАНО … НЕ РЕДАКТИРОВАТЬ`.
3. **Новые примитивы** кладём в `shared/ui/` и экспортируем из `shared/ui/index.ts`.
4. Компонент годится в `shared/` только если он не зависит от специфики одного
   приложения. Допустимая зависимость — `@/lib/i18n`: этот путь есть в обоих
   приложениях и резолвится в их собственный словарь.

## Почему генерация, а не npm-workspaces

`web/Dockerfile` и `admin/Dockerfile` собираются с контекстом `../web` и `../admin`
(см. `infra/docker-compose.full.yml`). Из контекста `web/` каталог `packages/`
**не виден**:

- `COPY . .` не заберёт файлы выше контекста;
- symlink наружу контекста Docker не разыменует;
- workspace-пакет `npm ci` внутри контейнера не найдёт (корневого
  `package.json` в контексте нет).

Любой из «красивых» вариантов потребовал бы поднять контекст сборки до корня
репозитория и переписать оба Dockerfile — то есть сломать существующий,
работающий контур ради удобства разработки.

Генерация раскладывает общий слой в обычные закоммиченные файлы внутри каждого
приложения. Для Docker это неотличимо от рукописного кода, для разработчика
источник по-прежнему один. Цена — необходимость запускать `sync.mjs` и держать
в CI `--check`.

## Что где

| Файл | Роль |
|---|---|
| `tokens.mjs` | все токены + обоснования шкал в комментариях |
| `sync.mjs` | генератор: CSS-блок + копирование `shared/**` |
| `MIGRATION.md` | таблица «старое имя → новое» и список ручных доделок |
| `shared/ThemeProvider.tsx` | тема auto/light/dark, `data-theme` на `<html>` |
| `shared/theme-init.ts` | анти-FOUC инлайн-скрипт для `layout.tsx` |
| `shared/I18nProvider.tsx` | язык tg/ru/en (словари — свои у каждого приложения) |
| `shared/ThemeToggle.tsx` | кнопка переключения темы |
| `shared/LangSwitcher.tsx` | segmented-переключатель языков (на тёмной подложке) |
| `shared/BrandMark.tsx` | марка «Метро Душанбе» |
| `shared/ui/` | примитивы: `Button`, `Card`, `Field`, `Badge`, `Alert`, `Container`, `Stack` |

## Использование в приложениях

```tsx
import { Button, Card, Badge, Alert, Stack, Container } from "@/shared/ui";
import { useI18n } from "@/shared/I18nProvider";
import { useTheme } from "@/shared/ThemeProvider";
```

Старые пути (`@/components/ThemeProvider`, `@/components/BrandMark`, …) оставлены
реэкспортами ради обратной совместимости — новый код импортирует из `@/shared/…`.
